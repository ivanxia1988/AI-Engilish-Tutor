## 状态与优先级

- `P0 / P1 / P2` 表示原 PRD 的开发阶段，不代表某项已经完成。
- `已整理` 表示文档已接入；`待决定` 表示产品规则仍有缺口；`待验证` 表示需要实测或当前官方资料核对；`待实现` 表示没有按本规格验收。
- 本次 SPEC 是原 PRD 的结构化草案，不把原文的“未核实”提升为已确认事实。
- 用户最新明确要求优先。产品规则参考 PRD；视觉细节参考 DESIGN。SPEC 对冲突的处理必须注明依据，无法确定的记入待决定事项。

## 每次开发怎么用

1. 确定任务对应的 `TK-R-*` 需求、页面和阶段；只处理本次范围。
2. 查 `TK-D-*` 是否影响本次实现；可逆的小实现选择沿用现有架构，产品取舍不默默补定。
3. 从 `TK-AC-*` 提取可复现的验收场景，补充本次具体实现计划及必要测试。
4. 修改代码和相关说明；接口、状态或规则变了，同时更新规格和场景。
5. 完成相关检查后记录实际结果。通过自动测试、真机体验、真实模型调用分别表述，不混写为已全部验收。

P0 优先验证从选课到真实课堂再到小结的闭环；P1 报告、设置和 P2 摄像头功能不因样图存在而提前实现。指标目标需要真实试用验证，不能为了达到开口次数强迫孩子重复。
