## 1. 背景和目标

很多家庭给孩子报了外教课，课本是固定的，但课后没人陪孩子把这本书「再讲一遍、再说一遍」。现有产品要么教自家内容（学习机、口语 App），要么能看课本但不会在页面上指着讲（豆包、ChatGPT 等通用 AI）。能「翻页 + 高亮 + 语音」的，目前只看到 LearnAloud、Onhand 等原型，面向成人、在电脑上用。

这个判断来自产品研究页，是我们自己的分析，不是已验证的结论（未核实是否完全没人做）。

- **目标 1** · **孩子愿意开口**：每节课（约 15 分钟）孩子开口 20 次以上，主动提问或打断至少 2 次。
- **目标 2** · **孩子自己回来**：不用家长催，孩子自己打开 Teeko 上课（见「压力测试」，这是要先验证的核心假设）。
- **目标 3** · **家长看得懂、放心**：每节课后一页报告；录音和学习记录可随时删除。

## UI 原则：极简

> **[info] 一句话**：上课对话时，屏幕上只留三样东西：课本页、老师头像、孩子自己的小窗。元素一多就会抢走孩子的注意力。参考图是一款儿童在线课的布局（左边大块课件，右边只有老师头像和孩子画面，几乎没有按钮和文字），只当灵感。

| 元素 | 对话时怎么处理 |
| --- | --- |
| 课本页 | 大，是唯一的视觉焦点；高亮、圈词、发音标记都只画在这里 |
| Teeko 小窗（右上） | 橙色小麻雀。状态靠 5 个姿势（听 / 说 / 递麦 / 想 / 开心）和嘴型表达，不用文字标签（见「Teeko VI 视觉规范」） |
| 孩子小窗（右下） | 就是「轮到你了 / 我在听」的提示：轮到孩子时小窗亮起橙色 #E07A3F 3 px 边 + 呼吸光晕 + 音量条（Teeko 同时做递麦动作），孩子开口后边变青绿 #2A9D8F、音量条跟着动。默认显示孩子头像；家长开启摄像头后可显示画面（见「摄像头感知」）。看到的信号只改变老师的话和动作，不加 UI |
| 字幕 | 默认关。孩子在 18 课中菜单里开关（家长区可改默认值）；上课画面不常驻字幕条 |
| 快捷按钮 | 不常驻。「再说一遍 / 慢一点 / 中文讲」变成语音指令（直接说 Again / Slower / 中文），另有一个收起来的菜单 |
| 进度 | 顶部一条 3 px 细进度线；不显示分钟数、星星、分数 |
| 翻页条 | 默认隐藏，老师自己翻页；孩子在课本上左右滑动或点边缘时才出现 |
| 提示和纠错 | 只出现在课本页上（虚线圈提示词、发音标记），不弹浮层、不开侧栏 |
| 家长、暂停、返回 | 收进一个角落的小图标，对话时半透明 |

和前面必须项的关系：轮次提示由「孩子小窗亮边 + 音量」和「课本上高亮要说的句子」完成，不再用文字状态和大按钮；卡住降难度的提示词、发音标记都画在课本原词上。旧 Figma「01 上课」已废弃，以本节为准。

| 字标 | Nunito Black（900）：「Tee」藏青 #1F2A44 +「ko」橙 #E07A3F | 只用在字标里；正文不用橙色字 |

| 奶油 cream #F6F1E7 | 页面背景 | — |
| 状态色（v0.3） | Teeko 在说 青绿光晕 #8CCFC6；在想 琥珀 #E3A21A / 点 #A87410；暂停 #A3AABD；重连 #5C6886 | 见「Teeko 轮次提示」。都配形状或动态，不只靠颜色 |
| 炭灰 charcoal #2B2D42、赤陶 terracotta #D96C4A | 本轮色板里的辅助色 | 设计包 v0.3 里没有，状态灯也没用到；赤陶和焦橙太接近。要不要留，待视觉确认 [warning] |
| 对比度禁令 [danger] | 不要白字压橙底（2.99:1）；不要在奶油底上用橙色小字（2.82:1） | 要用橙色文字时用深橙 #A44E20（5.37:1）；中文辅助字不浅于 #5E6478（数字来自设计包 DESIGN.md） |
| 字体 | 英文标题 Nunito，英文正文 Inter，中文 Noto Sans SC | 中文字体待定（Noto Sans SC 还是 HarmonyOS Sans SC） [warning] |
| 尺寸 | 可点区域 ≥ 56 px，主操作 64 px，麦克风 96 px；中文提示 ≤ 16 个字 | 来自 VI 页 |
| 语气 | 温暖、克制；表扬要具体（「你自己说出了 going to」），不说空泛的 Great；说错时用正确说法复述（recast），不说 wrong /「错了」 | 和「5. AI 老师规则」一致 |
| 评价 | 上课画面不显示星星和分数。星星（1–3 颗，#FCC23A，不显示 0 颗）只用在课后小结等课外页面；要再练的词用深橙 #A44E20 + 波浪线；不用红色、不打分数、不做排行榜、不做连续打卡 | 课中要不要给即时反馈，见「待夏诚决定」 [warning] |
| 小麻雀 Teeko · 姿势 | 5 个：听（待机，青绿声波，约 3.6 秒眨一次眼）/ 说 / 递麦（640 ms 弹簧动画，招牌动作）/ 想 / 开心 | 小麻雀本身的橙色（#EE7A30 等）只用在插画里，不当界面色；中文昵称未定 |
| 小麻雀 Teeko · 嘴型 | 4 个：闭 / 小 / 大 / oo；没声音时循环 16 帧 × 90 ms；有声音时每 80 ms 取一次音量（< 0.08 闭，0.08–0.32 小，> 0.32 大），每个嘴型至少停 80 ms | 系统开了「减少动态效果」时最快 180 ms 换一次 |

## 家长区：防误触门和设置

防误触门（26）：一道随机两位数以内的乘法题（比如 7 × 8），用屏幕数字键盘输入；算错 3 次要等 1 分钟；算对后 5 分钟内不再问，退出家长区就失效。它只是防孩子随手点进设置的「门」，10–12 岁的孩子都会算，所以不是安全措施，也不算「家长身份验证」。真正需要确认家长的动作（注销账号）用家长手机短信验证码；如果法务认为改设置也要确认家长，再把这里换成短信验证码（未核实）。

## 开课检查：设备和连接

每次上课前自动跑一遍，正常时孩子只看到四个青绿色 #2A9D8F 的「好」（P0 不开摄像头时是三个），点开始上课即可。麦克风不可用就不能开课；摄像头不可用可以开课，只是关闭摄像头感知；网络或回话速度「差」时仍可开课，但先提示。下面的阈值都是初始猜测，未核实，要在真实家庭网络里测了再定。

| 检查项 | 怎么测 | 好 | 一般 | 差 / 不可用 |
| --- | --- | --- | --- | --- |
| 摄像头 | 拿到摄像头权限并检测到人脸 | 能看到人脸 | 有画面但太暗或太远（给一次提示） | 无权限或无画面 → 关闭摄像头感知，可继续 |
| 麦克风 | 请孩子说一句话，3 秒内看音量 | 有清楚的声音 | 声音很小（提示靠近一点） | 没声音或无权限 → 不能开课，提示请家长去设置打开 |
| 网络 | 到我们服务器测 5 次往返时间和丢包 | 往返 < 100 ms，丢包 < 1% | 100–250 ms，或丢包 1–3% | > 250 ms，或丢包 > 3% |
| Teeko 回话速度 | 给实时语音接口发一段测试音频，量「说完 → Teeko 第一段声音到达」，测 3 次取中间值 | < 800 ms | 800–1500 ms（「可以上课，Teeko 偶尔会慢半拍」） | > 1500 ms（「网络有点慢，建议换个地方或稍后再试」，仍可开课） |

页面底部保留「摄像头已开启 · 家长同意，只看不存」这一行；家长没同意时这一行显示为「摄像头未开启」，摄像头那项直接跳过。

## 课后报告：自动生成

1. **下课触发**：这一课讲完、孩子说结束、或到了家长设的时长上限，都算下课；中途退出但上了 ≥ 3 分钟也生成一份简版（初始规则，未核实）

3. **家长报告后台生成**：后端用这节课的事件记录（开口、卡住、纠音、离开画面）和文字转写生成「学得好 / 要再练 / 在家可以」，目标 60 秒内完成（目标值，未核实）；失败自动重试，不需要谁点按钮
4. **通知和查看**：生成好后小结页显示「✓ 学习报告已自动生成」；家长在家长入口和首页「最近的课」里都能看到

## 摄像头感知：老师能看见孩子（P2）

> **[warning] 整块是 P2**：保留设计，但 P0 / P1 都不做。P0 试用时摄像头不开（14 权限说明只讲麦克风，05 里摄像头项显示「未开启」）。等「孩子自己回来」的假设过关、儿童图像合规问过法务后再做。下表「P2 第一批」是做 P2 时先做的。

> **[info] 一句话**：家长开启摄像头后，老师能「看见」孩子：孩子不在画面里，Teeko 会说「I can't see you!」；孩子竖大拇指，Teeko 当成 Yes。看到的东西只改变老师怎么说、怎么做，不在屏幕上加任何东西（遵守「UI 原则：极简」）。

- **开启方式**：可选功能，家长在家长端主动打开（opt-in），打开前用一屏说清楚看什么、不看什么、存什么。孩子小窗显示真实画面还是头像，家长另外选；两种情况下感知功能都能用
- **数据怎么走**：能在 iPad 上分析的都在本机分析；只把分析出的「事件」（比如 kid_left_frame）发给实时模型，不发画面。默认不上传、不保存原始视频和截图。不做身份识别，不给孩子贴情绪标签
- **另一种做法：云端截帧**：把画面每秒截一张发给多模态实时模型（见下面技术说明）。好处：能认出孩子举起来的东西，理解更丰富。代价：孩子的图像离开设备，合规负担更重；按图片计费，成本更高；延迟更大。建议只用于「Show & tell」，并且要家长单独开启、孩子举起东西时才截帧
- **合规**：儿童图像和人脸属于儿童个人信息，可能还是敏感个人信息。端侧分析、只发事件是否足够合规，未核实，上线前要法务确认

| 信号 | 老师怎么做（示例台词） | 批次（整块 P2） | 技术可行性备注 |
| --- | --- | --- | --- |
| 离开画面（3 秒以上检测不到脸） | 停下讲解：「Hey Leo, I can't see you! Where did you go?」10 秒后还不在就暂停整节课；回来时说「Welcome back! We were right here.」并重新高亮刚才那句 | P2 第一批 | 端侧人脸检测，最成熟。低头看纸质课本可能也会丢脸，阈值要实测 |
| 走神：头转开 N 秒（先定 8 秒） | 和页面挂钩地拉回：「Leo, look at the robot here. What can it do?」同时高亮那个元素。一节课最多拉回 2–3 次；不说「你没认真」 | P2 第一批 | 用头部朝向判断（人脸变换矩阵）；视线估计不准，不用。误判会让孩子觉得被盯着，宁可少报 |
| 手势答题：竖大拇指 = Yes，倒大拇指 = No，挥手 = Hello / Goodbye | 接在降难度最后一级后面：「Thumbs up or thumbs down?」害羞的孩子先用动作答，Teeko 再引导说一个词：「Thumbs up! Can you say yes?」 | P2 第一批 | MediaPipe 手势识别内置 Thumb_Up、Thumb_Down、Open_Palm 等类别（已核实）；挥手需要多帧判断「张开手掌在左右动」，要自己写 |
| 开课时光线太暗、脸太近或太远 | 只在开课时说一次：「It's a bit dark. Can you turn on a light?」/「Can you sit back a little?」课中不再反复提醒 | P2 第一批 | 画面亮度 + 人脸框大小就能判断，简单 |
| 动作表演（TPR）：jump、clap、wave 等动词 | 学到动词时：「Can you clap? Show me!」孩子做了就表扬。也是害羞孩子开口前的台阶 | P2 之后 | 拍手、跳需要身体姿态模型；iPad 前置镜头可能拍不全身体，准确率未核实 |
| 旁边出现另一个人，或有人小声给答案 | 友好地说：「Thanks for helping! Let Leo try first.」家长在旁边陪是正常的，不提醒 | P2 之后 | 多张脸好检测；判断「谁在小声说答案」要靠声音区分说话人，难度未核实 |
| 孩子指课本、举起一样东西 | Show & tell：「Is that a robot?」如果指的是页面插图里的东西，就高亮对应元素 | P2 之后 | 端侧只能知道「手里举着东西」「在指」；认出是什么要云端截帧。指纸质课本很难对应到页面坐标 |
| 表情像困惑、沮丧（低置信） | 孩子放弃前先放慢、提前降一级：「Let's do it together.」不说「You look confused」 | P2 之后 | MediaPipe 能给 52 个表情系数（已核实），但从表情推情绪不可靠，只用来调节奏 |
| 笑、兴奋（低置信） | 顺势表扬：「I love that smile! Let's keep going.」 | P2 之后 | 同上；误判代价低 |
| 疲劳：打哈欠、趴桌子 | 建议休息或缩短：「Want a one-minute stretch?」/「Shall we finish this page and stop?」只建议，不强制 | P2 之后 | 张嘴系数 + 姿态，误判多，需要连续出现才算 |
| 嘴动 vs 声音 | 孩子嘴在动才算孩子在说话；嘴没动但有声音（Teeko 的回声、电视）不打断 Teeko | P2 之后（看回声测试，可能提前） | 唇部开合来自人脸关键点，能缓解免按键的回声误触；和声音的对齐延迟未核实 |
| 孩子点头、挥手 → Teeko 头像跟着点头、挥手 | 镜像反应，让孩子觉得 Teeko 在看着自己、有回应 | P2 之后 | 只是头像动画，用已有的点头 / 挥手事件 |
| 口型：th、v / w、r / l | 「Put your tongue between your teeth, like this.」Teeko 头像示范口型 | 以后（实验） | 能看到嘴形，但判断发音对错没有现成方案，未核实 |

> **[warning] 低置信信号的规矩**：表情、疲劳这类信号不可靠：只用来调整节奏（放慢、降难度、建议休息），绝不对孩子说「你看起来很困惑 / 很累」，也绝不写进家长报告。任何信号都要连续出现几秒才算，同类提醒一节课有次数上限。老师不说「I'm watching you」这类话。

## 5. AI 老师规则

| 规则 | 说明 |
| --- | --- |
| 先指后说 | 讲到某句、某词前先高亮，再开口；高亮和语音的时间差目标 ≤ 200 毫秒（LearnAloud 的经验值）。按官方文档，GPT-Live 语音模型本身不调用工具，所以「先指」由我们的程序做：照讲解计划先在 iPad 上 highlight，再用 session.commentary.append 让 Teeko 讲这一句（见「OpenAI Live 委派模式」） |
| 只指已有元素 | 只能高亮解析出来的 element_id，不能凭空编位置；找不到就说「我们看第 X 行」并请孩子指给它 |
| 轮次提示 | 每段讲完必须把话轮明确交给孩子：课本上给要孩子说的那句铺淡橙底 + 孩子小窗亮起焦橙边和音量条 + Teeko 做递麦动作 + 一句英文邀请。孩子开口后小窗变青绿边、音量条跟着动；说完 1 秒内 Teeko 点头或简短回应，表示「听到了」。不用文字状态标签 |
| 打断 | 默认免按键：孩子一开口，老师马上停声（截断当前回复），状态切到「在听」；回答完问题后回到刚才那句，并重新高亮。环境吵或回声误触时，退回「按住说话」 |
| 卡住降难度 | 孩子 5–8 秒没开口或说「不会」：开放问 → 二选一 → 是 / 否，每降一级都在课本上圈出提示词（highlight style=hint）。不原样重复同一个问题 |
| 纠错 | 孩子说话时不插话；先用正确说法自然复述（recast），不说「你错了」；同类错误攒到这段讲完集中提一次。发音问题在课本原词上标出读错的音节和重音 |
| 即时反馈 | 每次开口后 Teeko 用一句具体的话回应（具体表扬或复述正确说法）。上课画面不显示星星和分数；要不要加视觉即时反馈，见「待夏诚决定」 |
| 不给整句答案 | 提示只给词或句型开头，让孩子自己说完；同一题不连续给完整答案，防止背答案 |
| 节奏 | 每段讲解不超过约 20 秒；每 1–2 句就让孩子开口一次（跟读、回答、造句）；一页讲完自动翻页，翻页前先问一句「准备好了吗？」。一节 10–15 分钟，到点问「要不要再学一页？」，不硬停（家长上限除外）；不突然弹窗 |
| 语言 | 英语为主；孩子连续两次没听懂，或说「中文」（语音指令，也可在收起的菜单里点），再用一句简短中文解释。家长开了「只说英语」模式时，不讲中文，改用降难度和圈词，「中文讲」语音指令和菜单项关闭 |
| 语气 | Teeko 是固定人设的老师，不是朋友：温暖、克制、不幼稚；表扬要具体（「你自己说出了 going to」），不说空泛的 Great；说错时用正确说法复述（recast），不说 wrong /「错了」，不打分数；不做情感陪伴、不说「我想你了」之类的话（参考对标第 7 条：人设能降低开口门槛，但不越界成陪伴） |
| 安全 | 不讨论与学习无关的话题，礼貌拉回；不收集姓名以外的个人信息 |
| 看见孩子 | 只在家长开启摄像头时生效。收到画面事件后用一句自然的话回应（见「摄像头感知」的台词），然后回到课本；同类提醒一节课有上限。不评论孩子的长相、表情和情绪，不说「我在看着你」 |

## OpenAI Live 委派模式：能力与落地

一句话：GPT-Live（模型 gpt-live-1）只负责「听和说」，查资料、用工具、动脑子的活都「委派」给后端。它自己不调用 highlight 这类函数，只发一个「我需要帮忙」的事件；后端做完，把结果用一句话交回，Teeko 再用自己的话说出来。孩子说话时它也能一边听一边说（全双工）。

委派有两种（官方指南里的两种），建会话时选定，换模式只能新开会话：

| 模式 | 怎么设 | 谁干活 | 适合 |
| --- | --- | --- | --- |
| Responses 委派 | delegation: { type: "responses", responses: { model, instructions, tools … } } | OpenAI 替我们调一个 Responses 模型（文档举例 gpt-6-luna，复杂任务 gpt-6-sol），自动带上对话上下文；我们只执行自定义函数并把结果交回 | 想省事；后端结果可以直接给 Teeko |
| 客户端委派（推荐 v1 用） [success] | delegation: { type: "client" }（填 null 也是客户端模式） | 我们自己的程序：自己存转写和课堂状态，自己挑模型或服务，自己检查结果再交给 Teeko | 要控制给模型看什么、结果先审再说、以后换国产模型——正好是 Teeko 的情况 |
| Decisions 委派（只在 API 参考里出现，指南没讲） | delegation: { type: "decisions", decisions: { model, questions } } | 把委派变成一组选择题 / 是非题 / 打分题，由 Decision API 回答 | 未核实，v1 不用；但同一套题目可以做成「触发器」，见下表 |

> **[info] 和之前的测试对上了**：10-29 测试用的是 Responses 委派，所以当时要用 response.item.create + response.create（文档写明这两个命令「需要 Responses 委派」）。客户端委派不用它们，改用 session.commentary.append / session.thinking.append / session.instructions.append 交回结果。连接地址都是 wss://api.openai.com/v1/live/sessions，模型 gpt-live-1。链接里的 delegation-mode 只有 client 和 responses 两个值，没有 server。

全部能力清单（按官方指南和 Primary WebSocket 参考整理，事件名照抄）：

| 能力 | API 事件或参数 | 文档说明 | 在 Teeko 里怎么用 | v1? |
| --- | --- | --- | --- | --- |

Teeko 的架构（客户端委派）：

**图（节点）**

- `kid` 孩子（Leo）（person）
- `ipad` iPad 前端：WebRTC 声音；课本渲染、highlight、turn_page；摄像头端侧分析；跟读录音
- `live` GPT-Live 语音模型：gpt-live-1：听、说、被打断、决定何时求助
- `srv` 我们的后端（旁路）：转写、页面状态、讲解计划、进度；把结果交回 Teeko
- `brain` 强模型：选动作、降难度提示、课本元素检索（目前测的是 gpt-6-luna，以后可换国产）
- `pron` 发音评分：讯飞 / Azure / SpeechSuper
- `trig` 转写触发器（decision）：想翻页？想找词？说不会？

**图（连线）**

- 孩子（Leo） → iPad 前端（说话 / 动作）
- iPad 前端 → GPT-Live 语音模型（麦克风音频）
- GPT-Live 语音模型 → iPad 前端（Teeko 的声音）
- GPT-Live 语音模型 → 我们的后端（旁路）（session.delegation.created + 转写）
- GPT-Live 语音模型 → 转写触发器（input 转写）（虚线）
- 转写触发器 → 我们的后端（旁路）（decision.event）（虚线）
- 我们的后端（旁路） → 强模型（转写 + 页面元素 + 工具定义）
- 强模型 → 我们的后端（旁路）（highlight / turn_page / 提示词）
- 我们的后端（旁路） → iPad 前端（执行 highlight(element_id) / turn_page(n)）
- iPad 前端 → 我们的后端（旁路）（完成回执；kid_left_frame 等事件）
- iPad 前端 → 发音评分（跟读录音）
- 发音评分 → 我们的后端（旁路）（分数）
- 我们的后端（旁路） → GPT-Live 语音模型（commentary / thinking / instructions.append）

两条主路径：

1. **A. 照计划讲课（大部分时间）**：后端按讲解计划：先发 highlight 给 iPad，前端画完回执 → 再发 session.commentary.append（delegation_id: null）「Explain p12_s1: I like apples. Then ask Leo to read it.」→ Teeko 开口。这样「先指后说」由程序保证。从 append 到真正出声的延迟还没测（未核实）
2. **B. 孩子主动要求（找词、翻页、要提示）**：Teeko 判断要求助 → session.delegation.created → 后端马上发空 thinking 让她别说空话 → 强模型从转写里选动作 → iPad 执行 → 确认成功后发 commentary「Done: apple is circled」→ Teeko 说出来。实测约 2.8–3.4 秒
3. **C. 提前做（可选）**：转写触发器在孩子话还没说完时就给出「想找词 0.77」，比委派事件早约 2 秒；置信高时前端可先高亮，委派到了直接复用结果
4. **D. 摄像头事件**：端侧算出 kid_left_frame(5) → 后端决定说不说 → 要说就 commentary「Leo seems to have left. Say: I can't see you! Are you there?」；要她立刻停讲就用 instructions.append

等待、打断、取消、出错：

| 情况 | 文档怎么说 | Teeko 怎么做 |
| --- | --- | --- |
| 后台在跑时 Teeko 说什么 | 可以提示词让她先应一句；acknowledgement_delay_ms 内发任何 thinking / commentary 就取消自动应答；她说「我看看」不等于真的开始干活 | 短任务（< 1 秒，如翻页）不说话；长任务（如生成提示、评分）发 thinking「Lookup in progress.」，并在提示词里给一句固定话：「Hmm, let me look…」；超过 3 秒再发一次 commentary 说进度 |
| 孩子打断 Teeko | 语音会停，但后台任务继续跑；要不要取消由我们决定 | 每个任务带版本号；孩子改口（「不是 apple，是 banana」）就把旧任务作废，晚到的结果丢掉不说 |
| 取消任务 | Live 没有「取消委派」命令；要在后端取消，确认取消成功后再告诉用户 | 能撤的（高亮）直接 clear_marks；翻页类先确认再说「OK, staying on page 12」 |
| 必须马上闭嘴 | instructions.append 可以打断；但已经播出的声音收不回，要绝对安静得在播放端静音、丢掉缓冲 | 孩子离开画面、家长来叫停时：iPad 先本地静音，再发 instructions |
| 出错 / 超时 | 重试前先查原动作是否已经做了；结果不明就直说 | 后端给每个动作 3 秒超时（我们定的，未验证）；失败就 commentary「I couldn't find it. Can you point to it?」，不重复翻页 |
| 会话到时长上限 | session.closed 的 reason 为 expired | 自动新开会话，把讲解进度和最近转写放进 session.input；时长上限是多少文档没写（未核实） |

> **[success] 已实测（2026-10-30，合成语音，脚本在 /workspace/live-test/）**：客户端委派全流程跑通 2 次：两次都收到 session.delegation.created（target: client），强模型（gpt-6-luna）都选对了动作（highlight(p12_w_apple, circle)、turn_page(13)），Teeko 都是等结果来了才说「I circled it」「Page 13」，没有先说空话。转写触发器也跑通：孩子说到一半就判出 page_intent=highlight，比委派事件早约 2 秒。

> **[warning] 文档没说清 / 未核实**：① 会话时长上限多少没写；② 用 commentary.append（null）驱动讲课、到 Teeko 真正出声要多久，没测；③ Decisions 委派只在 API 参考里有，指南没讲；④ 触发器的 kid_confused 判断是看整段转写，孩子说过一次「我不懂」后一直是 1.0，要改题目写法；⑤ 真人孩子口音、iPad 回声、打断停声时间都没测；⑥ OpenAI 不对中国大陆开放，这套只适合原型演示（见风险表）。

| 价格 | gpt-live-1 每分钟 $0.05，按秒计；后端模型和工具另算（OpenAI 价格页，2026-10-30 查） | 按 token。北京区 qwen3.8-omni-flash-realtime 每百万 token：输入 文本/图片/视频 1.5 元、音频 6 元；输出 文本 4.5 元、音频 12 元（音频和对应文字都收）；新开通送 100 万 token、90 天。qwen3.5-omni-plus-realtime 贵得多（输入音频 80 元/百万） | 官方没写每秒音频折多少 token，一节课的估算见「成本模型」（未核实） | 用 qwen3.8 flash 跑一节 20 分钟课实测 token |

> **[info] 结论：差距有多大**：「听、说、看」这层 Qwen 不比 GPT Live 差，有几项还更好：能直接看图和视频、VAD 能调、会话时长写清楚、国内能用、价格明确。真正差的是「委派」这一层：GPT Live 能一边陪孩子说话，一边让后台慢慢想，想好了随时塞回去让 Teeko 说；Qwen 只有传统工具调用——模型发起、我们回填、再让它说，中间没法随时塞话。对国内上线的意思：委派这层我们自己做。我们 v1 本来就选了「客户端委派 + 自己后端」，所以后端（强模型、高亮、翻页、发音）不用改，要重写的是「把结果交回语音模型」这一步。上 Qwen 前先实测三件事：① Qwen 直接调 highlight / turn_page 准不准、多快；② 等工具时 Teeko 能不能先说一句、孩子打断后晚到的结果还能不能回填；③ 中途 session.update 改 instructions 是否生效。要拿到北京区 DashScope Key 才能测。

## 6. 课件制作流程（内部）

> **[info] 谁用这套流程**：只有我们自己。制作 Teeko 内置课件时离线跑，再人工校对元素框和讲解计划；孩子端没有识别等待，也没有上传入口。

1. **导入课件原稿**：有授权的课件原稿（PDF / 图片）；检查清晰度
2. **版面解析**：MinerU 或 PaddleOCR PP-StructureV3：文字块、图片块、阅读顺序、坐标
3. **视觉定位**：Qwen-VL / Gemini 等视觉模型给插图里的物体加框；每个元素存为 {id, type, text/label, bbox}
4. **生成讲解计划**：按页列出要讲的句子、单词、提问，引用 element_id
5. **上课时**：把当前页元素列表用 session.thinking.append 放进实时会话；后端（不是语音模型）决定 highlight / turn_page，前端按 bbox 画标记

v1 课件提前处理好，不占上课时间。
