更新时间：2026-10-31。依据：本轮用户讨论、原型审阅与[当前 SPEC](../specs/teeko-v1/spec.md)。本文是后续开发使用的决定摘要；[原始 PRD v0.2](PRD.md)保持原文，不将其中待定参数自动升级为已确认要求。

详细行为以 [SPEC](../specs/teeko-v1/spec.md) 和[验收场景](../specs/teeko-v1/acceptance.md)为准；界面路径见[页面流](../design/page-flow.md)，技术边界见[Railway 架构方案](../plans/2026-10-31-teeko-architecture-design.md)。用户最新确认优先于旧 PRD、设计样图和历史计划。

## 1. 产品定位与当前范围

Teeko 是一个爸爸在陪孩子学英语、摸索方法的过程中，结合自己的 AI 能力制作的英语陪练工具。公开页面与计划中的小红书个人 IP 保持一致：讲真实的缘起、尝试的方法和工具怎么用，邀请有需要的家庭一起试用、交流反馈。语气温暖、克制，少营销口号，不编造家庭经历、资质、用户见证、成绩或免费承诺。

| 项目 | 当前决定 |
|---|---|
| 用户与设备 | 8–13 岁孩子；电脑和平板浏览器；一个账号对应一个孩子。年龄按 8–9、10–11、12–13 岁点选 |
| 内容 | 人工准备、校对并发布的内置课程；平级主题列表，一课一个主要开课动作，无学校年级、学期或单元层级 |
| 公开介绍 | 可滚动长页，依次说明缘起、方法、使用步骤、邀请与家长问题；不受课堂一屏操作要求限制 |
| 应用操作 | 选课、开始、暂停、继续、结束等主要动作尽量在当前视口完成；报告和长列表用分区、页签或分页 |
| 分享方式 | 邀请码由本人私下发放，公开介绍可直接浏览，首次注册需要邀请码 |
| 教师角色 | 橙色小麻雀 Teeko；页面中的照片质感儿童是 AI 生成的演示人物，不冒充作者家人或实际课堂采集 |

关联：TK-R-001/002/003/017/024/025。

## 2. 加入落地页后的产品路径

原型保留 00–29 的来源屏号，共 27 个有效状态；01 的邀请码、邮箱验证、设密码属于同一账号页的子状态，不增加三个独立页面。原型路径用于开发审阅；正式 `/` 与 `/login` 已独立，后续账号后的路由仍须在后端接入时落实。

| 场景 | 主路径与分支 |
|---|---|
| 新用户第一次来 | 00 公开落地页填写并验证邀请码（也可从01注册入口验证）→ 01 邮箱验证码 → 设置并确认密码 → 02 孩子档案 → 完整流程的 16 首次首页，或 P0 的 04 课程列表 |
| 邀请失败 | 空、无效、过期、停用、已使用分别反馈；校验本身不消耗名额。只有完成注册才绑定并消耗；已使用码提示已有账号登录 |
| 老用户回来 | 00 的登录入口或 01 → 邮箱密码登录 → 已建档进入学习首页，未建档继续 02；不重新填写邀请码 |
| 找回密码 | 01 → 邮箱找回验证码 → 重置密码 → 回密码登录；不消耗新邀请码。正式服务须撤销旧会话并处理活动课堂 |
| 第一次上课 | 首页或 04 选课 → 14 权限说明 → 05 开课检查；失败到 15 重试，成功后首次进入 17 介绍/定级，再进 06–10 课堂 |
| 日常上课 | 首页继续上课或进入 04 我的课程列表 → 开课检查 → 课堂；跳过已经完成的首次说明与定级步骤 |
| 暂停与恢复 | 课堂 → 18 主动暂停或 11 互动暂停 → 继续/结束；20 断线重连独立处理，恢复原有效上下文，结束后的迟到回调不能复活课堂 |
| 一课结束 | 19 结束说明/确认 → 12 即时小结，详细报告先显示整理中；允许离开，完整流程后续从最近的课 → 23 全部报告 → 13 单节报告查看 |
| 查看与调整 | 25 我的 → 02 档案编辑、27 教学偏好、28 隐私或 29 帮助；设置不经过家长算术题 |

P0 不依赖 P1 首页或报告列表：结束、重连失败返回 04；即时小结与后台报告任务可独立交付。旧链接 22 → 12、24 → 03、26 → 27 保留兼容，目录不恢复这些已退役页面。完整状态、前后入口与异常流以[页面流文档](../design/page-flow.md)为准。

邀请码退出规则：离开注册、回全貌或通过地址切页时撤销临时邀请/邮箱证明并清空密码草稿；已创建账号和已消费邀请码记录保留。正式服务必须在服务端执行验证、到期、停用和并发兑换，不能信任前端标记。

## 3. 课堂体验的共同规则

- 教材为主，右侧上下排列老师与孩子的矩形会议式窗口，分别展示连接状态。P0/P1 不采集摄像头，孩子使用头像；关摄像头、未出镜或无人脸不能成为暂停依据。
- 老师围绕目标灵活提问，先听孩子说完；卡住时给图片、线索、二选一或换活动，尊重暂时跳过和拒绝重复。跳过不记作掌握，提示后完成不记作独立掌握。老师风格再严厉也不能羞辱或循环逼读。
- 教材工具只保留指针、画笔、撤销；用同一画笔自由画圈答题。笔迹在教材和提示上方、课堂弹窗下方，指针不挡内容点击；换题、暂停或结束后的旧模型结果不能继续落地。
- 正确、错误、模糊选择要有对应反馈；已确认的正确回答或努力可触发短鼓励、烟花、贴纸与轻音效，不做积分榜或扣分。音效可关闭，减少动画偏好生效，重复事件不重复奖励。
- 持续没有有效互动、环境嘈杂或交流不清时，先等待和轻提示，再用老师第一人称说明暂停原因；不能只因短暂沉默、一次识别失败或音量大就立即暂停。检测阈值与恢复条件待真实家庭音频验证。
- 暂停菜单只保留继续、结束。课中退出的防误触采用二次确认和浏览器离开提醒；不恢复家长答题。区分主动中途结束、内容学完、课时时间到、单课硬上限和每日上限；只有主动结束可取消返回原课堂状态。
- 先显示事实有限的即时小结，详细报告异步整理，可能需要几分钟。练习建议依据具体卡点、老师纠正和随后表现，不用泛化家长话术代替课堂证据，也不从文字转写推断发音分数。

关联：TK-R-004–016、018–022、102/103；具体结束与报告参数保持待定，不把原型数字写成产品承诺。

## 4. 设置、服务选择与已取消内容

教学偏好保留授课语言（全英文/允许中文辅助）、老师风格（温柔/认真/严厉）、声音（女声/男声）、GPT Live/通义选择、连接检测和互动音效。实际声音须映射供应商可用配置。保存的风格不能覆盖尊重拒绝、不逼读等共同教学原则。

选择 GPT Live 时提示浏览器网络、VPN/代理可能影响连接，并由用户主动检测；不声称识别了 VPN 开关。静默握手检测成功仅说明相应连接测试完成，不等于真实音频、长连接或后台委派全部可用。部署 Railway 也不保证浏览器媒体直连在所有网络可达。

本轮明确不恢复：单元与单元完成逻辑、单词本、家长算术门槛、课中字幕/中文讲解/重说菜单、“慢一点”按钮、独立圈选/橡皮/清空/颜色面板、课堂供应商/共享课本标签、家长时间边界和通知数据设置页签。中文辅助是否允许由教学偏好控制。视频观察属于 P2 独立规格；多孩子、用户上传课本、支付、作业批改不进入当前最小闭环。

## 5. 技术架构倾向与确定程度

| 部分 | 当前方向 | 状态与边界 |
|---|---|---|
| 部署 | Railway 为正式部署平台；Cloudflare 仅可选 DNS | **用户已选定**；不再比较是否换回 Cloudflare 计算、D1/DO/Workflows。尚未完成正式迁移 |
| Web 与课堂控制 | 常驻 Node Web/API/应用 WS，首版一个 Web 副本；同仓库按模块分工 | 当前架构倾向。已通过独立 Next Node 生产构建与本地 HTTP 切片；Node WS/正式认证/PG仍待G0，现有 wrangler 开发运行不等于生产方案 |
| 权威状态 | PostgreSQL 保存账号、版本化课程、进度、课堂租约、额度、证据和持久任务 | 当前架构倾向。内存仅持有活动连接与取消句柄，浏览器 IndexedDB 仅缓存；不让断线/重启重置额度或终态 |
| 后台任务 | 独立 Jobs 进程生成报告、重试清理、恢复卡住任务 | 当前架构倾向。任务落库、幂等和可重领，不依赖 HTTP 结束后的临时 Promise；首版不强制 Redis 或微服务集群 |
| 文件 | 优先验证 Railway 的 S3 兼容 Bucket，版本化课程资源与私有文件分开授权 | 候选接入；地域、CORS、签名访问、缓存和费用待验证。不默认保存儿童原始音视频 |
| 邮件与认证 | Resend 发验证码邮件；服务端账号、密码、Cookie 与邀请准入独立管理 | **Resend 已指定**；Better Auth + Drizzle PostgreSQL 是候选，须验证邀请 → OTP → 设密码、找回和账户激活的完整流程 |
| 实时语音 | GPT Live、通义各自适配供应商协议，共用受控的应用层语义 | 分别验证。GPT 服务端 sideband 尚未接入；通义正式 Node WS 中转与强制关闭需 G0 实测，不能直接照搬 append 事件 |
| 复杂教学与视觉 | 独立 TeachingBackend、VisionInspector、报告生成；实时模型负责实时对话 | 当前架构倾向。语音、推理、视觉、报告模型分别配置；已知教材对象先几何解析，必要时才检查图片 |

服务选择也决定允许的数据路线：用户选通义时，不可未经说明又把孩子的转写或教材截图静默送到 OpenAI 后台。跨供应商组合须明确配置，不自动跨供应商故障切换。工具动作先验证课程对象、会话/页面/活动版本、权限与当前状态，再提交；模型建议和供应商回执都不直接当作已执行或已说完。

正式准入、租约、额度、单次邀请码和报告写入由服务端与数据库执行；密钥只留服务端。详细的事务、连接关闭、任务幂等和部署交接方案以[架构文档](../plans/2026-10-31-teeko-architecture-design.md)为准，不在产品摘要中冻结供应商 API 或数据库实现细节。

## 7. 后续交付顺序

1. **G0 验证正式基础设施与契约。** Railway Node 生产入口、同源 HTTP/WS、PG、Bucket、邀请/邮件样例、两家控制与关闭能力；优先发现运行时和协议差异。
2. **G1 打通真实账号与课程。** 正式公开落地页 → 邀请 → 邮箱/密码 → 档案/偏好 → 课程与恢复；验证账户隔离、邀请码并发单次兑换和持久化。
3. **G2/G3 做一节真实课，再接第二家。** 先一份人工校对课程、一条供应商路径，将动作回执、版本失效、暂停/结束/重连跑通，再完成另一家及教学风格映射。
4. **G4 异步报告。** 课堂证据、结算状态和报告任务可靠落库；报告整理、重试与具体练习建议可追溯，失败不阻塞下课。
5. **G5 受控家庭试用。** 目标设备、真实网络、噪声与误暂停、发布恢复、预算与备份演练，各自记录证据。

用户已同意并实际采用 git worktree 分步并行开发；首批Node HTTP与任务上下文两条独立分支已通过检查并集成，记录见[并行计划](../plans/2026-10-31-parallel-foundation.md)。先固定模块输入/输出和验收，再拆分独立任务；共享契约和集成测试作为汇合点，每批验证后合并。并行开发不代表提前宣称某项 G0 验证、正式部署或试用验收完成。具体任务状态以[实施待办](../specs/teeko-v1/tasks.md)和对应实现计划记录。

## 8. 正式交付与审阅边界

用户再次确认：目录、屏号、路线、设备切换、情景与模拟结果均为内部审阅工具，真实产品不呈现。正式网站从 `/` 公开介绍进入 `/login`，不通过 `/prototype` 验收。原型账号与正式入口隔离；开发 `/preview` 只用于无框视觉验收，不代表真实上课能力。实现和测试见[拆分记录](../plans/2026-10-31-product-review-separation.md)。

## 9. 真实账号后端接入状态

已完成正式邀请→邮箱验证→设密码→PG账号/会话→孩子档案的本地实现和实际Node验证。发码为管理CLI导出给运营者私下分发，验证不占名额，注册单事务核销；停用、过期、已用与并发竞争由数据库判定。Resend既有auth.teeko.app已验证，发件用hello@auth.teeko.app，无需改网站域名。

正式前端已改真实API请求，未配置服务时如实错误；不再是静态不可用占位。正式课程未发布时返回真实空列表，不显示原型课程/报告。协议正文提供试用审阅稿，匹配版本由运营者明确启用。本批尚未部署到Railway、未创建线上PG或实际发邮件，课堂/额度/报告继续后续接入。详见[账号运行说明](../backend/accounts.md)。
