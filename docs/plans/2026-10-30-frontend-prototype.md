# Teeko Frontend Prototype Implementation Plan

**Goal:** 提供可审阅的 29 屏网页原型，支持电脑与平板一屏操作，业务数据全部模拟。

**Architecture:** 在 `/prototype` 添加独立客户端入口；纯 TypeScript 管理页面目录及关键跳转，React 组件提供状态化页面，作用域 CSS 保持原课堂不受影响。复用已归档 SVG 与 tokens，静态素材复制到原型专用 public 目录。

**Tech Stack:** 现有 React / TypeScript / Vinext / Lucide，Node test runner；不新增依赖。

## Task 1: 页面流与测试

- 新建 `lib/prototype-flow.ts` 与 `tests/prototype-flow.test.ts`。
- 先验证 01–29 完整、无失效跳转，P0 不依赖 P1 首页，完整体验进入正常首页，暂停继续返回正确状态。
- Run: `node --import tsx --test tests/prototype-flow.test.ts`。先观察缺少模块的失败，再实现目录和跳转使测试通过。

## Task 2: 原型入口与组件

- 新建 `app/prototype/page.tsx`、`components/prototype/prototype.tsx`、`components/prototype/prototype.css`。
- 增加流程总览、阶段/分组目录和演示状态切换。
- 完成登录建档、首页选课、检查/引导、课堂状态、报告、我的、家长区、帮助及数据管理。
- 原型模拟状态不调用真实 API，也不申请麦克风/相机。

## Task 3: 布局与素材

- 将需要的 SVG、tokens 与现有字体复制到 `public/prototype-assets/`，保留字体许可。
- 使用视口高度、弹性网格、页签和分页，使按钮固定可达；电脑与平板均保持一屏核心操作。
- 课本上标记不重排内容；课堂暂停菜单、字幕开关和重连可点击验证。

## Task 4: 核对与交付

- 同步 SPEC 的网页/电脑/平板范围及前端原型状态，不更改原始 PRD。
- Run: `npm run typecheck`，按失败定位，相关测试通过后进行构建检查。
- 浏览器打开 `/prototype`，走首次路径、异常恢复和家长报告路径；检查桌面/平板视口的主要操作均可见。
- 保存实际截图，报告访问地址、覆盖页面和模拟服务边界。
