## 真实 AI 路径

配置后可使用以下服务端接口，密钥不会发送到客户端：

| 接口 | 行为 |
| --- | --- |
| `GET /api/status` | 返回是否完成 AI 配置、是否登录；不返回密钥 |
| `POST /api/analyze` | 将选中的教材页发送给视觉模型，结构化生成对象区域和课程 |
| `POST /api/teacher` | 发送当前教材与孩子圈画的合成图、对象、当前步骤和最近对话，得到双语回复与高亮动作 |
| `POST /api/transcribe` | 转写一段主动录制的语音；识别文字可以检查后发送 |
| `POST /api/live/session` | 使用服务端 Secret 创建 Live 会话，只返回 SDP、会话 ID 和绑定当前用户、会话及有效期的应用票据 |
| `POST /api/live/agent` | 客户端委托后台：校验会话票据，用当前任务与带时间戳的转写生成回复或课堂动作，也检查持续跑题 |
| `POST /api/live/diagnostics` | 校验会话票据后记录操作事件、状态注入确认和错误码，不记录音频、转写、教材文字或密钥 |
| `POST /api/live/close` | 校验当前登录身份与签名票据，关闭对应会话 |

AI 不能自行翻页或让未完成任务过关。圈选由应用做几何判定；口语答案先核对示范表达，其他表达可由 AI 判断。AI 对象坐标和所有课程引用都会验证，不可靠的解析返回错误，并保留上传预览供修改/重试。

GPT-Live 路径使用 `gpt-live-1`、`gleam`，会话选择 **客户端委托**（`delegation.type=client`、`acknowledgement_delay_ms=800`）。我们的 `/api/live/agent` 独立调用 `gpt-6-luna`、low reasoning，维护最近带时间戳的双向转写和当前任务，不使用 Live 管理的 Responses 委托。点击“开始实时课堂”后才请求麦克风，音频通过 WebRTC 传输，字幕与委托事件通过数据通道接收。新增国产服务的配置、传输与能力差异见下方“国产实时语音对照”。

收到 `session.delegation.created` 后先发送同一 delegation ID 的空 `thinking.append`，再执行后台任务。后台返回高亮、答案核对或页面检查动作，由应用校验并执行，然后通过同 ID 的 `commentary.append` 返回确认结果。重复 delegation ID 不重复执行，换题或停止后的旧结果不生效。文字输入也走自己的后台，不发送 Responses 模式专用的 `response.*` 命令。界面变化发送自然语言形式的状态差异，包括选择、自由笔画的颜色/类型/边界和命中对象、撤销、清除及老师圆圈；不重发完整后端指令。只有匹配的 thinking.appended 确认全部到达后，界面才显示“教材与标注状态已送达老师”。

明确的英语/中文画圈指令还会从孩子的累积转写中识别，等待约 700ms 稳定后由程序直接执行，不依赖语音模型是否发出委托；否定、词义问题、不完整单词和歧义目标不会直接执行。晚到的原生委托不会重复画圈。画圈采用真正的 SVG 椭圆覆盖在已知对象上，等待界面有机会绘制后才回报确认。

三个课堂动作继续使用 `highlight_objects`、`submit_spoken_answer`、`inspect_current_page`。视觉检查复用当前教材与圈画的合成图；Live 语音前端不直接接收图片。转写片段不能直接判分。课堂不开放通用网络搜索。实时通话中的圈选反馈和下一题读题不受设备自动朗读开关影响。

实时带课还包含独立的静默引导器。它从浏览器本地的麦克风/老师接收流计算能量，不录音、不上传音频样本。只有两路采样均新鲜（1.5 秒内）且确认老师已发声，才会把后续安静视为思考等待。等待约 8 秒后先换一种具体问法，之后分别等待约 12 / 16 秒，给提示、句型支架、示范后再试。连续无人回应最多三层，不循环催促；这些是发出请求的时间门槛，实际出声还受模型和网络影响。

引入听力步骤及应用已确认正确的步骤，在老师声音结束且安静约 6 秒后允许应用调用下一步，未完成练习绝不靠沉默过关。静音、正在画画、后台工作、语音待播放或状态待确认时不催促；缺失播放确认会记录诊断而不是当成讲完。明确的暂停请求会关闭主动带课，'等等/让我想一下'暂缓；查询 stop 的词义不会误关闭。界面提供每次会话的主动带课开关。引导被记为辅助，不能计入首次独立答对。

教学口吻由 `lib/teaching-style.ts` 统一，强调适龄、尊重、根据回答具体反馈、一次一个问题、描述/比较/应用，避免低幼称呼和反复夸奖。演示口语题接受完整描述句，不要求只重复孤立单词。

老师的插话规则允许在持续无关讲话时温和抢回话头。应用在持续收到孩子转写约 10 秒后检查内容，检查间隔至少 8 秒、提醒冷却至少 20 秒；仅凭讲话时长不会触发。正常长回答、跟读、中文求助、思考和口吃不应被当作跑题。检查只允许提醒或等待，不能判分或执行工具。等待中的提醒遇到停一下、求助、换题、静音或讲话中断会丢弃。页面上的“请老师带回课堂”可直接试一次程序触发的提醒。

这些时间是应用的检查门槛，不是保证发声时刻；转写、网络和后台推理会增加时间。插话通过 Live 行为规则和实时指令实现，不强制关闭孩子的麦克风，实际能否自然抢回话头需真人试听。没有接服务端 sideband，实时控制目前由浏览器数据通道发出。

结束、暂停、离开课堂或页面进入后台时，停止声音采集并结束连接；优先等待 `session.closed` 确认，必要时使用签名票据请求服务端清理。一次连接最多 10 分钟，不自动重新连接。家长设置提供不采集声音的 recvonly 连接测试，连接后自动关闭。

单句录音作为备用路径：录音 → 转写 → 文字确认 → 老师回复 → 设备朗读。无 API 时仅在浏览器支持的情况下提供设备语音识别。

## 本地运行

需要 Node.js 22.13+ 和 npm。首次安装后：

```sh
npm ci
npm run dev -- --host 127.0.0.1 --port 5173
```

```sh
/Users/zhanghai/.cache/codex-runtimes/codex-primary-runtime/dependencies/node/bin/node scripts/run-framework.mjs dev --host 127.0.0.1 --port 5173
```

若系统 PATH 中没有 Node，请把上面路径的 `bin` 目录加入 PATH；项目的工具脚本会启动 Node 子进程。

### 配置真实 AI

1. 复制 `.dev.vars.example` 为 `.dev.vars`。这个文件被 Git 忽略。
2. 在服务端填写 `OPENAI_API_KEY`，保持密钥私密。可通过 OpenAI Developers 插件的密钥流程配置，勿在孩子界面输入。
3. `OPENAI_MODEL` 默认 `gpt-6-astra`，`OPENAI_TRANSCRIBE_MODEL` 默认 `gpt-transcribe`。实时模型由 `OPENAI_LIVE_MODEL`、`OPENAI_LIVE_VOICE`、`OPENAI_LIVE_BACKEND_MODEL` 配置。使用有权限且支持所需能力的模型，费用由 API 账号承担。
4. 完成适用于目标年龄、地区和数据的提供商及产品配置后，才将 `OPENAI_CHILD_DATA_READY` 设为 `true`。此变量只是运营者声明，不会启用提供商的任何数据保留功能，也无法证明配置正确。
5. 重启服务。在“家长设置”中检查连接；本地开发需要点击登录链接，通过 starter 提供的本地模拟登录建立身份。生产站点公开浏览，AI 接口使用 Sites 登录身份校验。
6. 首次语音/AI 使用前，请家长阅读并开启应用中的授权选项，再回到课堂点击“开始实时课堂”。浏览器需要 HTTPS 或 localhost 和麦克风权限。

当前站点已按所有者授权配置服务端 Secret，并依据所有者对项目已启用 ZDR 的确认启用了真实课堂。密钥不包含在源码、ZIP 或前端中；应用无法自行证明提供商组织的 ZDR 审批，运营者需持续保证其适用。

儿童数据处理：OpenAI 的 [Under-18 guidance](https://developers.openai.com/api/docs/guides/safety-checks/under-18-api-guidance) 对处理 13 岁以下或当地适用数字同意年龄以下儿童个人数据提出先实施 API 零数据保留的要求。`store: false` 只控制一部分应用状态，**不等同于组织/项目已批准和启用 Zero Data Retention**。请核对账号、模型和具体端点的适用条件：[数据控制文档](https://developers.openai.com/api/docs/guides/your-data)。未确认时请保持真实 AI 关闭，用演示或手动备课验证产品。

生产环境使用 Sites 原生的环境变量/Secret 配置；不要把密钥写进 `.openai/hosting.json`、源代码或公开仓库。环境变量修改后需要重新部署对应版本。

在课堂或家长设置中选择服务，检查该服务的配置状态，再手动点击开始实时课堂。**既有“不采集声音的连接测试”仍只验证 GPT-Live**，不能据此证明国产服务可用；国产服务需要在填好对应配置后实际开始课堂验证。切换服务前先结束当前通话，避免把不同连接的音频和指标混在一起。

阿里使用浏览器 WebRTC 音频路径。豆包与智谱当前使用网站后端的 WebSocket 转发，录音和声音播放采用浏览器 AudioWorklet/PCM 流；网站托管在 Cloudflare，线路仍包含浏览器到网站以及网站到服务商两段，**不是原生国内部署，也不能保证因此消除跨境路径或获得更低时延**。若需要测纯国内服务链路，之后还需把相同转发层部署到可访问提供商的国内环境，并单独比较。

课堂仍使用已知对象的本地画圈、操作状态同步和应用确认，支持静默带课提示、插话取消及拟人头像。各服务的原生 API 能力并不完全等价；不能把 GPT-Live 的委托、转写或控制语义原样当作其它服务支持。豆包当前的文字接口只做直接播报，**不将文字语义问答伪装成原生支持**：请使用麦克风进行语音问答；已知目标的文字画圈指令仍可由应用本地执行。豆包的教学提示先从当前步骤生成实际可听口语，避免把控制指令读给孩子。

新增统一性能导出保留 `provider`、`transport` 与 `model`（请求配置中的模型，并非已验证的上游最终模型），可用同一教材、设备、网络、轮次和实验标签做对照。阿里/GPT 的 WebRTC 统计与豆包/智谱的 WebSocket 统计不可直接混作同一种链路指标：`websocket_ping` 只测**浏览器到网站**的往返，不含网站到语音提供商的完整路径；`playback_queue` 表示浏览器待播放音频长度，也不是网络 RTT。WS 路径没有的原生 RTC 丢包、抖动等字段保留 `null`，不填零，不代表“没有丢包”。旧版本性能 JSON 仍可读取，缺少厂商字段时按原有 GPT-Live / WebRTC 路径解释，未记录模型时保留未知。

播放队列超过 2 秒、音频格式异常或采集积压时会明确提醒并结束音频管线，不默默大量丢弃旧音。正常说话停顿不算卡顿；主观“刚才卡了一下”与 JSON/CSV 导出仍可用于对齐排查。

官方接入文档：[阿里通义 WebRTC 接入](https://help.aliyun.com/en/model-studio/realtime-webrtc-access)、[豆包 Seeduplex 3.0](https://docs.volcengine.com/docs/doubao-voice/end-to-end-real-time-voice-full-duplex-version?lang=zh)、[豆包接入说明](https://docs.volcengine.com/docs/doubao-voice/access-must-read?lang=zh)、[智谱实时 API](https://docs.bigmodel.cn/cn/guide/models/sound-and-video/glm-realtime)。

## Railway 部署

仓库根目录的 `Dockerfile` 与 `railway.json` 可用于 Railway 构建和部署。容器沿用 Workers 运行时，由 `scripts/start-railway.mjs` 监听 `0.0.0.0:$PORT`；健康检查为 `/api/network-check`。Railway 提供 HTTPS，启动脚本通过 `RAILWAY_PUBLIC_DOMAIN` 恢复服务端请求的公开来源。

本地密钥、缓存和构建产物不会进入 Docker 构建上下文。服务端变量应在 Railway 的 Variables 中配置，不要提交到 Git。教材、设置和学习记录仍保存在访问者的浏览器中。

此部署使用 Wrangler 的本地 Workers 运行时，适用于当前演示和迁移验证。Railway 不提供原 Sites 的 ChatGPT 登录网关，因此这里保持 AI 接口未登录，拒绝信任外部传入的 Sites 身份头。页面、手动备课、上传及演示练习可用；真实 AI 和实时语音需要另行接入适用于 Railway 的登录，单独配置密钥不能解锁。此容器尚不能作为正式儿童课堂服务的生产部署验收。

## 流畅度记录与请求路径

实时音频不是由项目后端逐包转发：

- 建连：浏览器产生 SDP → `/api/live/session` → OpenAI Live → SDP 回到浏览器。
- 连接建立后：浏览器通过 WebRTC 与 OpenAI 交换麦克风、老师音轨及实时数据事件；需要时媒体路径可使用协议协商出的中继。
- 明确的已知对象画圈：浏览器识别指令 → 本地绘制并确认 → 数据通道通知 Live。此路径不需要 Luna 或视觉请求。
- 复杂委托：浏览器 → `/api/live/agent` → Luna → 浏览器；需要看未知标注时，再调用 `/api/teacher` → 视觉模型 → 浏览器；最后通过数据通道让 Live 说明结果。
- 诊断请求异步发送元数据，不承载实时音频，也不参与回复的等待链路。

课堂中展开“家长调试 · 流畅度记录”：每 2 秒通过 getStats 采样 RTT、抖动、区间丢包、抖动缓冲、补偿样本、码率和可用的上行指标。缺失字段保留 null，首次采样建立基线；处理 SSRC 改变、计数重置和迟到包恢复。正常语音停顿不算卡顿，补音/丢包只是相关线索。

记录还拆分麦克风授权、ICE、建连 HTTP、首个接收音频、状态注入确认、Luna 排队/请求、工具及视觉请求、浏览器计时器延迟。服务端返回 `performance` 元数据和 `Server-Timing`：`serverTotalMs` 包含校验与后台处理，`upstreamMs` 包含上游网络、服务处理及读取响应，不能等同于纯推理耗时。客户端 HTTP 往返减服务端耗时也不能得出单向网络时延。HTTP 统计可能包含失败/超时尝试，应结合状态日志看待。

`child_to_teacher_gap` 由本地声音能量估算，排除重叠讲话和程序主动触发的输出；它不是精确回合结束事件、纯模型耗时或扬声器实际声学延迟。老师的正常思考、700ms 指令稳定窗口、8/12/16 秒带课提示和 6 秒自动衔接是不同概念，不能都归为网络卡顿。

可以点击“刚才卡了一下”，将主观感受对齐到采样时间线。实验标签只标记 baseline/network_a/network_b/prompt_a/prompt_b，不会自动修改网络或提示词；每条样本/事件保留当时标签，界面统计汇总当前保留数据的全部标签，分别比较时请筛选导出 CSV 的 strategy 列。

支持 JSON/CSV 导出，保留本机最近 3 次不同会话；每次最多保留最近 400 条采样与 400 条事件，UTC 起始时间加相对毫秒可用于时间对齐。每 10 秒保存一次快照，正常结束时再次保存；清除本机数据也会清除性能记录。窗口异常退出时可能损失最后几秒数据，浏览器存储不可用时仍可导出本次内存中的报告。

服务端现有诊断日志约每 10 秒收到一次 RTC 数值摘要，记录手动卡顿标记、请求耗时和状态。应用新增的性能报告、诊断记录与导出均不包含音频、对话正文、教材正文、IP、SDP、候选地址或密钥。性能面板本身在本环境完成组件/导出及算法验证；真实浏览器 getStats 和扬声器听感需要实际连接后采集。

## 公开访问与网络提醒

网页公开访问；匿名访客可以浏览教材与体验演示练习，真实 AI 课堂和 AI 备课仍需登录及既有家长授权。登录前不会为实时课堂请求麦克风。

打开网页会向本站 `/api/network-check` 连续发起 3 次不缓存的轻量请求，不调用模型、不打开麦克风。中位耗时超过 800ms、耗时波动超过 600ms 或部分请求失败时显示提醒；全部失败显示检测未成功。离线事件会提示可能离线，并保留手动重试入口。检测结果不阻止使用教材。

该检测仅反映到网站的连接，不能保证浏览器到 OpenAI 的语音线路正常。通话后使用既有 WebRTC 统计继续检测：RTT >600ms、抖动 >80ms、缓冲 >300ms、丢包 >5% 或补音 >3% 属于较差信号；连续 2 次出现才提醒，连续 3 次有效正常采样恢复。无统计数据时不会宣称线路恢复。
